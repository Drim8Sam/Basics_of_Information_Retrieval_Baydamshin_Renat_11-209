# Release Notes 

## Web Crawler Homework (Task 1)

Этот проект представляет собой простой веб-краулер на Python, написанный в рамках учебного задания. Он скачивает HTML-страницы из предварительно заданного списка, сохраняет их в текстовые файлы и создает индексный файл.

- Скачивает 100 HTML-страниц из списка `urls.json`.
- Сохраняет содержимое каждой страницы (вместе с HTML-разметкой) в отдельный файл в папке `crawled_pages`.
- Создает файл `index.txt`, где каждая строка содержит номер файла и соответствующий URL.

После выполнения программы в директории проекта появятся:
Папка `crawled_pages/`, содержащая файлы `1.txt`, `2.txt`, ..., каждый из которых — содержимое соответствующей скачанной страницы.
Файл `index.txt`, в котором каждая строка имеет вид: `<номер_файла> <URL>`.

Также был написан метод, который очищает скаченные страницы, от тегов `script`, `style`, `link`, `noscript`, `iframe`, `meta`. При этом сохраняет html структуру страницы для последующих задач.

Установить зависимости:

```bash
pip install requests
```

Запуск:

```bash
python main.py
```

## Page Processing Homework (Task 2)

Вторая домашняя работа выполняет обработку HTML-документов, скачанных в первом задании, и строит:
1) список уникальных токенов корпуса (без мусора и служебных слов);
2) группировку токенов по леммам (используется стемминг Портера).

## Функциональность

### 1. Чтение HTML-документов
- Считывает файлы из директории:
  - `WebCrawler/crawled_pages/*.txt`

### 2. Извлечение текста из HTML
- Извлекает видимый текст из HTML.
- Игнорирует содержимое тегов:
  - `script`, `style`, `noscript`
- Декодирует HTML-энтити (например, `&amp;` → `&`).

### 3. Токенизация текста
- Извлекает слова, состоящие **только из латинских букв (ASCII)**.
- Приводит токены к нижнему регистру.
- Удаляет:
  - стоп-слова (предлоги, союзы, местоимения и т.д.);
  - слова короче 2 символов;
  - мусорные токены:
    - токены с не-ASCII символами (например, `ılbır`);
    - повтор одного символа (`aaaaa`, `bbbbbbb`);
    - чрезмерно длинные фрагменты.

Результат токенизации — **уникальные токены** (без дубликатов).

### 4. Лемматизация (нормализация) и группировка
- Для каждого токена вычисляется “лемма” как основа слова с помощью стеммера Портера (Porter stemming).
- Группирует токены по леммам.
- Формат строк в файлах лемм:
  - `<лемма> <токен1> <токен2> ... <токенN>`

### 5. Создание выходных файлов
После выполнения создаются:

- `Task2/tokens.txt` — список уникальных токенов корпуса, по одному в строке.
- `Task2/lemmas.txt` — лемма и связанные с ней токены в одной строке через пробел.
- `Task2/tokens_per_doc/{id}_tokens.txt` — уникальные токены для каждого документа.
- `Task2/lemmas_per_doc/{id}_lemmas.txt` — леммы и токены для каждого документа.

## Использование

1. Убедитесь, что после первого задания есть файлы:
   - `WebCrawler/crawled_pages/1.txt`, `2.txt`, `3.txt`, ...

2. Установите зависимость:
   ```bash
   pip install nltk
   ```
3. Запуск:
   ```bash
   python Task2/task2.py
   ```

## Boolean Search Homework (Task 3)

Третья домашняя работа реализует инвертированный индекс и булев поиск по документам, обработанным во втором задании.

### Функциональность

#### 1. Построение инвертированного индекса
- Читает файлы токенов из `Task2/tokens_per_doc/*_tokens.txt`
- Создает структуру данных: термин → множество ID документов
- Сохраняет индекс в файл `Task3/inverted_index.txt` для повторного использования

#### 2. Булев поиск
- Поддерживает операторы: `AND`, `OR`, `NOT`
- Поддерживает скобки для группировки выражений
- Приоритет операторов:
  1. Скобки (высший приоритет)
  2. NOT (унарный оператор)
  3. AND
  4. OR (низший приоритет)

#### 3. Формат запросов
- Простой термин: `algorithm`
- Бинарные операторы: `algorithm AND search`, `algorithm OR search`
- Унарный оператор: `algorithm AND NOT tree`
- Сложные выражения со скобками: `(algorithm OR search) AND NOT tree`

### Использование

1. Убедитесь, что выполнено Task 2 и существуют файлы:
   - `Task2/tokens_per_doc/1_tokens.txt`, `2_tokens.txt`, ...

2. Запуск:
   ```bash
   python Task3/task3.py
   ```

3. Введите булев запрос в интерактивном режиме.

4. Для выхода введите `exit`, `quit` или `q`.

### Выходные файлы

После выполнения создается:
- `Task3/inverted_index.txt` — инвертированный индекс в формате: `термин doc_id1 doc_id2 ... doc_idN`

## TF-IDF Processing Homework (Task4)

Четвёртая домашняя работа выполняет расчёт **TF-IDF (Term Frequency – Inverse Document Frequency)** для коллекции документов.  
Расчёт выполняется на основе выкачки из `WebCrawler` и результатов обработки из `Task2`.

---

## Функциональность

### 1. Использование результатов Task2
Программа читает данные, подготовленные во втором задании:

- `Task2/tokens_per_doc/` — уникальные токены по документам (для расчёта DF терминов).
- `Task2/lemmas_per_doc/` — леммы по документам (для расчёта DF лемм).
- `Task2/lemmas.txt` — соответствие **термин → лемма** (чтобы корректно агрегировать TF по леммам).

### 2. Расчёт Document Frequency (DF)
Для каждого термина и леммы считается **df** — в скольких документах они встречаются:

- `df(term)` берётся по `Task2/tokens_per_doc`
- `df(lemma)` берётся по `Task2/lemmas_per_doc`

Эти значения используются далее при вычислении IDF.

### 3. Расчёт TF-IDF
Для каждого документа из `WebCrawler/crawled_pages`:

- извлекается текст из HTML;
- выполняется токенизация для подсчёта частот (список токенов **с повторами**, чтобы посчитать TF);
- рассчитываются TF, IDF и TF-IDF:

**Термины**
- `TF(term) = count(term) / total_terms_in_doc`
- `IDF(term) = ln(N / (1 + df(term)))`
- `TF-IDF(term) = TF(term) * IDF(term)`

**Леммы**
- `TF(lemma) = sum(count(terms_of_lemma)) / total_terms_in_doc`
- `IDF(lemma) = ln(N / (1 + df(lemma)))`
- `TF-IDF(lemma) = TF(lemma) * IDF(lemma)`

Где:
- `N` — общее число документов в коллекции,
- `df` — число документов, содержащих термин/лемму,
- `total_terms_in_doc` — количество терминов в документе (после фильтрации).

### 4. Создание выходных файлов
Для каждого документа создаются два файла в директории:

- `Task4/lemmas_terms_per_doc/{doc_id}_terms.txt` — TF-IDF для терминов
- `Task4/lemmas_terms_per_doc/{doc_id}_lemmas.txt` — TF-IDF для лемм

Формат строк в файлах:
- `<термин> <idf> <tf-idf>`
- `<лемма> <idf> <tf-idf>`

Значения `idf` и `tf-idf` сохраняются с точностью до 6 знаков после запятой.

### Формулы

- **TF** = `(количество вхождений термина в документе) / (общее количество терминов в документе)`
- **IDF** = `log(N / (1 + df))`, где:
  - `N` — общее количество документов.
  - `df` — количество документов, содержащих термин.
- **TF-IDF** = `TF * IDF`
